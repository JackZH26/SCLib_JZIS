# Versioned backend activation and local rollback

Migration 0110 adds operator acceptance references, append-only activation
events and a guarded current v2 pointer. It leaves all v1 generation/resource
identities and history intact. No public route, ingestion writer, cache or
frontend switches as a result of installing this component. The coordinated
[migration plan](PGVECTOR_MIGRATION_PLAN.md) release gates still apply.

The publisher is a separate `sclib_retrieval_publisher` NOLOGIN group. Neither a
reader nor builder membership grants this authority. The disposable vector
runner provisions this group only in its fresh owned cluster; production role
and credential provisioning remains an operator task. The runtime API must
never be its member and cannot grant itself this role.

An acceptance record references thirteen reviewed artifacts: English relevance
for 240 queries, difficult filtered cases, 60 Ask cases, 60 Similar papers,
twice-peak load, site integrity, native new-paper/correction publication, queue
replay, roles, restore, standby and signed image. The database requires a closed
set of exact artifact hashes and binds the build/content/root/policy/image to a
fresh successful full readback. These references are explicitly **operator
attestations**. Neither this SQL nor `record_operator_acceptance` verifies the
external files, scientific labels, signatures or test truth. No passing report
is generated by that method. The authorized operator must review actual
artifacts before recording them. Synthetic rehearsal references grant no
production/scientific acceptance.

Activation rechecks the exact immutable records, fresh successful readback and
the same sealed physical table/index plus write guards. Full readback uses
only the private build fence before this operation. The global source/index
fence is acquired only for the short predecessor check and event/pointer move;
no full corpus scan occurs under that global fence. The private service bounds
statements to two seconds and lock waits to 250 milliseconds. Its caller owns
the outer commit and must not keep earlier long validation transactions open
across publication.

The initial v2 transition requires the actual current v1 generation, activation
event and manifest. Its content must be the complete retained generation.
Later transitions compare the exact v2 event, reject mixed v1 predecessors and
allow forward native content only from the current content base. Rebuilding
the same content can select a different sealed local graph. Event numbers and
derived bindings are assigned by SQL. Preview and exact replay preserve all
rows and epochs; conflicting identities and stale predecessors fail.

Rollback requires a previously active retained local build and a fresh full
binary validation. It appends a new event, with a new read/cache identity,
without restoring an old whole database over users or source records. It does
not reactivate Google ANN. A new, separately named trigger on v1 activation
events fences old writers after v2 takes authority. The original v1 functions
and event bytes remain unchanged. Both CAS and old writes use the existing
epoch so stale repeatable-read writers fail instead of missing a committed v2
pointer.

`load_active_backend` uses SELECT only and resolves the complete current
authority chain plus physical index/write guards. It returns a frozen v2 pin
with content/build/event/root/profile/policy identities and a private derived
projection address. No fake v1 generation or provider resource is constructed.
Its immutable profile is stored as canonical JSON text to prevent nested
mutation. `assert_current_backend` rejects a superseded pin. This is only the
authority component: readers must still bind every candidate to its member,
check source-use/lifecycle/evidence, preserve historical warnings, enforce one
pin across the whole request and recheck currentness before publication.

All acceptance/event history is append-only. Direct pointer edits/deletion are
refused. Downgrade refuses any retained acceptance/event/pointer. The empty
boundary removes only its own named v1 fence and compares every prior SQL row,
function and trigger. Populated rehearsal performs initial v1 transition,
selection of a distinct local graph and a fresh-validation rollback; a refused
downgrade preserves all public rows/functions/triggers and private object OIDs.
Without the owned vector runtime, populated activation checks are explicitly
not run.

Observed locally: 130 combined extension/transport/native/content/backend/
activation tests passed on fresh owned PostgreSQL 16.15. Full extension-enabled
schema rehearsal completed with cleanup verified. The no-extension rehearsal
separately completed with populated activation checks explicitly not run.
Another 98 legacy generation/corpus/metadata/HTTP compatibility tests passed.
