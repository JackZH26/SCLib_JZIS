## 1. 先确保验证过程不会接触真实数据

新增唯一受支持的 API／迁移测试入口 `scripts/run_disposable_tests.py`。入口只创建本次专用服务，不接受复用外部 DSN，不附着开发或生产服务，也不读取生产配置作为测试连接目标。

- 在导入应用／数据库客户端之前验证环境、私有能力文件、短期运行身份、精确连接摘要、随机端口和服务归属；直接运行未授权 API pytest 会拒绝执行。
- 连接后再次核对 PostgreSQL 专用角色／运行标记与 Redis 运行身份；测试角色不能管理其他数据库或 Redis 服务。
- 清理只作用于本次创建的进程、容器和私有临时数据。最终测试运行已正常清理这些一次性资源，没有删除用户数据。
- CI 改为锁定依赖安装并输出实际运行时清单；原生本地运行是可验证的替代路径，不冒充生产镜像一致性证明。

操作契约：[TESTING_SAFELY.md](../../TESTING_SAFELY.md)。早期阶段记录：[EN01_EN04_Implementation_2026-09-06.md](EN01_EN04_Implementation_2026-09-06.md)。该阶段记录中的初始 API 失败数是当时结果；本文下方为修复并整合后的最终回归结果。

## 2. 科学数值不再被强行压成单个浮点数

新增共享科学数值解析器，保留原始文本、单位、上下文／定位信息、解析版本和可追踪的解释结果。例如 `1e-3 K` 保留为 `0.001 K`；`20 kbar` 可规范为 `2 GPa`；区间或单边界限不能凭空生成中点或精确值。

- 不确定度、约数与解析失败原因保留为结构化元数据。只有具备点估计的记录可以填充兼容标量字段；不把兼容字段误称为完整科学表达。
- 材料提取、claim 映射和氢化物提取使用同一解析策略。
- 氢化物标量表无法直接接收的区间／同位素提案仍保留；提案日志必须先持久化成功，才允许后续 SQL 写入。
- 新增只读本地 JSONL 影响审计工具，生成确定性清单。它不连接数据库，也不自动回填。

局限：旧系统已经丢失的原始单位不能从现存浮点数可靠还原；本轮不以猜测补齐。遗留科学阈值／异常过滤的完整替换仍属 SC03，不因新增解析器而自动完成。

详细契约：[SCIENTIFIC_PARSER_CONTRACT.md](../../SCIENTIFIC_PARSER_CONTRACT.md)。

## 3. 统一“结果是什么”与“结果来自哪里”

建立 `sclib-result-origin/v1` 契约，分离：

- `knowledge_origin`：Observed / Computed / Inferred / AI-Proposed / Unknown。
- `source_role`：primary / cited / unknown / conflicted。
- 分类状态、冲突原因和分类器版本。

只使用明确的结果级标签和允许的方法标识。论文类型、压力、来源等级、引用次数、提取器名称，以及旧 `is_theoretical=false` 均不能单独证明结果是实验观测。LLM 从实验论文抽取结果与 LLM 生成材料假设是不同事件。

实际接入包括：

1. 材料聚合不再把“不是理论”自动计入实验池；列表／详情检查旧实验／理论汇总值是否得到原始结果支持，无支持则隐藏该分项，不重新编造最大值。
2. 搜索和论文详情返回显式分类；Ask 使用有大小限制的材料／分类摘要，不外泄任意嵌套提取载荷。
3. Timeline 的实验筛选只接受来源已解析为 Observed 且角色无冲突的结果。未知、计算、推断／AI 提案和冲突使用不同标记及英文说明。
4. 新增迁移 `0046_result_origin`，为可重建 Timeline 投影添加分类信息和版本标记；旧投影失效，分类器版本参与就绪判定和缓存键。
5. 分类是派生解释，不写回原始提取记录；API 导出再导入不会仅因新增分类信封而制造新的来源记录身份。实际原始科学字段改变仍改变身份。

API 与 ingestion 分别部署，暂采用字节一致的分类器副本，并用同一份 15 案例 golden fixture 和字节一致性测试防止分叉。

**Observed 不等于已确认体超导，也不等于被人工批准或独立复现。** 本轮没有把分类标签转换成超导概率、数据质量评分或已校准的 RPS。

详细契约：[RESULT_ORIGIN_CONTRACT.md](../../RESULT_ORIGIN_CONTRACT.md)。

## 4. 同位素先识别，未解决之前不产生伪精确特征

组分解析器升级到 `1.1.0`，在 Unicode／LaTeX 标准化之前识别同位素质量数、D／T 别名及电荷标记，同时保留原始写法和定位信息。不能可靠解释的同位素／电荷公式会被隔离，不输出普通元素质量冒充的精确描述符；普通元素 Dy 不会误拆为 D 和 y。

当前兼容字段中的 `composition_status=invalid` 配合 `isotope_or_charge_requires_resolution` 表示“当前解析器不能安全给出精确解释”，**不是材料在物理上无效**。精确同位素质量／丰度模型不在本批实现范围。

## 5. Discovery 保证一页数据属于同一个有效版本

- 服务端与拉取脚本共用严格校验模型，拒绝重复键、重复材料 ID、非有限数值及不合约字段；保留真实上游已有的合法扩展字段。
- 材料 feed、元数据和摘要作为同一原子快照发布，持久化最近一次有效版本，服务重启后仍可恢复。
- 更新失败保留最近有效数据并明确显示 stale 状态；没有有效数据时返回不可用，不用占位材料冒充真实 feed。
- 列表、后续分页和详情绑定 `data_version`：版本错配返回 409，缺少必要绑定返回 428，没有有效数据返回 503。前端会停止混合旧／新结果并提示重新载入。
- 只读校验当前上游 268 个候选材料及元数据／摘要通过；没有发布或修改上游数据。这是接口兼容性验证，不是对 268 个候选的科学真实性背书。

新增网站文案、图例和错误提示均为英文；没有改变原始文献文本或用户内容语言。之前的布局预览与研究评分功能保留，但不宣称其已完成 DR01／DR04／AL01 科学验收。

详细契约：[DISCOVERY_FEED_CONTRACT.md](../../DISCOVERY_FEED_CONTRACT.md)。

## 7. 发布前检查与回退原则

1. 将当前工作区既有改动和本批改动整理为可审查的提交／PR，保留原始研究方案和用户改动；不能把整个脏工作区未经审查直接发布。
2. 在 Linux CI 完成受保护的 API／迁移测试和 EN04 发布镜像清单比较，再运行前后端联动验收。
3. 对真实数据执行**独立批准的只读影响审计**，抽查来源分类、单位转换、同位素隔离与旧汇总值变化。不得把新分类器静默应用为人工审核结论。
4. 核对实际部署数据库的迁移起点；`0046` 依赖已有本地 `0045_research_shadow`，不得假定生产库已经具备该版本。制定备份、迁移窗口和回退预案后另行执行。
5. 新 Timeline 代码／刷新任务必须在新增列存在后启用，并与前端分类契约同步发布。旧投影只可重建，不可用于掩盖未知来源；回退需协调应用版本，不能一边运行新代码一边删除新列。
6. Discovery 发布前确认 pull 与 API 对缓存目录的读写权限、严格校验解释器和最近有效快照持久化。先验证失败时保留有效数据／显示 stale，再切换正式 feed。
7. 优先回退应用和可重建读模型，不删除或覆盖原始科学记录、旧解释及已发布研究快照。生产回退命令需基于实际部署状态另行核定。
