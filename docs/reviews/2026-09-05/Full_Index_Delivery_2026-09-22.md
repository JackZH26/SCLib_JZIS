# 全量检索兼容与发布记录（2026-09-22）

当前状态：全量嵌入执行中。生产仍使用旧版；本文中的分区探针、合成测试和云端小样本均不是全量上线验收。

## 实现

- `0079_retained_legacy` 保存原有论文、文本和精确重切分窗口。新的 `retained_legacy_snapshot` 明确保留历史解析链未确认状态，不补造历史 parser、原文抓取、抽取父记录或科学评审。
- `0080_index_corpus` 将完整 generation 组织为最多 20,000 个不可变分区，每区最多 1,000 个成员、16 MiB 快照。每条路由校验连续序号及累计字节预算，成员校验实际字节，封存再独立核对数量、字节和完整 manifest。旧版有界 generation 的限制不变。
- 实际模型响应记录关闭截断、768 维 float32、文本/向量摘要和 provider token statistics。调用前持久化预算与尝试；失败和中断不退回预算。超长输入单独登记，替换窗口完整覆盖受影响的原始文本，原始回执保持不变。
- 全量 operator 分别执行 plan、stage、publish、observe、activate。完整输入和回执清单是发布前提；逐区实际读回后才能建立新鲜全量验证，再以 CAS 激活。云端读回只证明已声明 ID 的完整性，不宣称枚举并排除了所有孤立点。
- Search/Ask/Similar 读取同一个激活版本。Similar 复用已验证的文档向量；公式导航使用有界候选检索。旧文本提供带来源限制的检索/摘录，不能变成已确认科学结论；缺少抽取父记录的定量问答明确返回未命中。
- 输入导入只创建新的重放 chunk，在同一事务内移除这些临时重放行，保留不可变检索快照和旧 chunk；不会用旧副本覆盖生产用户数据。

## 只读计划优化

进一步实测表明，可以省去计划阶段的临时导入。新的 `plan_completions` 只读取当前原始 chunk/paper，并用 PostgreSQL 的实际类型和同一摘要函数计算计划；正式 stage 仍经过原来的全部 INSERT 守卫。22 项相关 native 检查通过，覆盖计划不写库、逐字段与真实 SQL 成员一致，以及源文本改变后拒绝旧计划。随后 131 项检索/接口捕获及 2,342 项离线测试、97 个 subtests 通过。新捕获 r5 校验 302/612 个当前源文件摘要。

实际副本上的 500 条真实嵌入计划用时 2.148 秒，与随后正式导入取得的全部成员字段完全一致；计划阶段没有新增保留记录，正式探针事务随后回滚。旧版运行中 handler 对 0080 副本的 health/version/stats/materials/paper 五个读取均返回 200；这只说明这五条读取兼容，不能据此声称旧镜像能够在新 schema 上通过原启动入口重启。
