# SCWiki editorial and implementation pilot

This branch adds an isolated, read-only superconductivity wiki to the existing SCLib frontend. It has not been deployed to production. No backend, literature RAG, material data or crawler permission policy is changed.

The authoring directory is `frontend/content/scwiki/articles/<code>/`: English body Markdown plus metadata. Run `pnpm build` to validate content, build the deterministic catalogue/index and compile Next.js. `pnpm test:scwiki-content` verifies that committed generated files match the sources. The source inventory is reproducible with `python3 frontend/scripts/scwiki-source-inventory.py /path/to/pinned/source` against commit `0a7c9d6696804ec26aa12f8eed68b55c9b3c0fcf`. It covers all 282 Markdown files and reserves IDs for the 88 topics; only the 12 pilots have routable article bodies.

Article IDs are `scwiki-a1` etc. Topic IDs use `scwiki-topic-a1`. Source-file IDs are hashes of repository/path, while primary-reference IDs are hashes of case-normalized DOI. Revisions hash the authored metadata and English body; catalogue revisions hash the article revisions. A primary source's publication status is separate from the editorial check scope. Metadata checks, syntax checks and historical audit scores do not verify scientific claims.

The pilot is an edited English synthesis, with source commit/path/hash, contiguous source-line dispositions, claim-to-reference mappings, mathematical assumptions, material conditions, limitations and review scope. Only specifically listed primary abstract/text checks were performed. Most citations have bibliographic identity checks rather than a full primary-results review. No independent replication or raw-data reanalysis is claimed. New unverified 2026 quantitative source-note claims are not promoted into the temperature comparison.

The correction register records the C2/C10 DOI `10.1103/PhysRevLett.109.087001` material mismatch (KFe2As2, not P-substituted Ba122), and C2's Christianson material attribution (K-doped Ba122, not Co-doped). B12 explicitly states the energy-cutoff convention; G7 removes categorical QSL/BCS claims; H2 separates residual and inelastic scattering definitions. Spectroscopic gap temperatures have their own kind and reported scale; `tcK` stays null for them.

The renderer is independent of the Ask-oriented MarkdownAnswer. It accepts GFM and mathematics, skips raw HTML, uses sanitization before KaTeX, disables trusted KaTeX commands and allows only bounded local raster image paths. Unrecognized diagram/code blocks remain inert. Scientific tables scroll locally on small screens.

`/api/scwiki/v1` serves articles, sections, sources, topics, search, Markdown and OpenAPI 3.1 from the same catalogue. It does not generate answers. A condition filter must match one material record; unknown does not satisfy a named condition. A spectral gap scale cannot satisfy a minimum-Tc filter. Search normalizes chemical subscripts, supports aliases/DOI, and does not index unpublished source chapters or the Al-O prediction note.

Navigation is Search → SCWiki → Materials → Reported Tc Timeline → Discovery → About JZIS. Exact docs landing paths redirect to SCWiki; docs API/data remain. Legacy docs anchors move to Using SCLib, which retains the prior getting-started content. Unknown article and API IDs return 404. Semantic server HTML, canonical metadata, visible-source JSON-LD and lastmod values use the authored records. The scoped llms.txt is a retrieval guide, not a crawler authorization or an indexing promise.

The existing sage palette, Inter typography, 10px controls, light theme, skip link, mobile menu and focus behavior are preserved. The new surfaces are research documents rather than marketing imagery or a visual redesign.

Standalone tracing and the runtime Dockerfile explicitly retain content and its build scripts. The owned public E2E copy includes content/scripts and rebuilds the index. Tests mock or deny the existing API, and production builds for this private preview use an inert server API. No real Ask requests are required.

Required frontend validation: frozen pnpm install, source/component tests, content freshness check, build, production mobile E2E and production dependency audit. GitHub CodeQL, repository-wide backend integration and release gates remain required before any separately authorized production merge or deployment; local frontend results do not substitute for them.

The public browser harness uses one canonical http://localhost:3102 origin because the installed Next.js URL adapter canonicalizes IP loopback hosts. Its request and WebSocket guard still rejects every other origin; this does not relax the production Host policy. Accessible article links include their visible “Read article” wording and source links use the existing darker sage token.

This VPS preview is a separate standalone runtime with an anonymous, inert wrapper for the old API. The wrapper is outside the application patch and is supplied in the handoff bundle. Its only published port is VPS 127.0.0.1:3107; a private SSH tunnel is needed for remote viewing. It runs as the existing image's node user with a read-only root filesystem, two CPUs, 4 GiB RAM and no host bind mounts or Docker socket. The 6 GiB development toolbox is separate. No production runtime configuration or reverse proxy was changed.

Acceptance on 2026-10-17: 49 source tests and 3,206 component tests passed (three pre-existing integration preparations remained skipped); after the final accessibility edits, all 14 SCWiki component tests, content freshness, all 44 public browser tests and the production build passed. The original full-suite results and the final targeted rerun are distinguished in the handoff evidence. The production dependency audit had zero high/critical findings, four moderate and one low; the advisory IDs and severities exactly matched the pinned base. These retained findings are release-review work, not a zero-vulnerability claim.
