# SCLib Materials 与 Discovery 2.0 综合实施方案

本方案延续 `materials_upgrade_plan_2026_10_01.md`，并依据用户提供的
`SCLIB_Discovery_2.0_Core_Methodology_2026.md` 扩展 Discovery。后者是研究
框架讨论，不能充当具体材料的实验证据；四项相加与配对通道分解也不是定量物理定律。

目标是让研究者能从材料记录走到可追溯的物理问题和下一步行动。页面需要明确区分
已保留记录、论文来源候选、外部参考、用户假设、计算预测与受限范围的科学审查。
页面布局改好、论文读到数据、字段正式补齐、线上发布通过是不同的完成条件。

## 1. 两页的共同研究单位

`Host + Modification + State + Conditions + Action`。

材料页回答“哪些结果在什么条件下被报告，缺什么以及如何补”。Discovery 回答
“希望改变什么物理条件，哪些证据支持这个问题，以及算或测什么最能改变研究决策”。
同一化学式不能替代样品、相、结构、状态或计算链的关联。

## 2. 材料字段补全路线

| 字段 | 优先补全途径 | 外部资源适用范围 | 何时需要新计算或实验 |
|---|---|---|---|
| Tc、判据、压力、方法、样品形态 | 当前记录对应论文、表格、补充材料，保留 source spans | SuperCon/MDR 等可提供报告线索；需核对原论文及样品 | 检索范围确实关闭且研究需要新结果时；访问失败不能解释为论文未报告 |
| 相、空间群、晶格、坐标、占据 | 论文结构表、补充 CIF，与样品及条件绑定 | MP/COD 为结构参考；公式相同不建立相同状态 | 无相符结构时才提出结构搜索、弛豫或结构表征 |
| Formation/hull、电子态、弹性与声子 | 论文或相符的已发表计算链 | MP/NOMAD 的实际结构、方法、输入、条件、run 元数据须匹配 | 有明确结构和模型问题后计算；0 K/特定模型结果不自动证明300 K常压稳定 |
| λ、ωlog、μ*、α²F及 Tc solver | 同一结构/压力/电子态/DFPT/Tc计算链，原单位与假设分开 | NOMAD 的相符 run 可提供参考；不能跨run组装 | 模型适用性、输入和收敛预算明确后才做新的EPC与Tc计算 |
| 非声子配对、关联、竞争序、相干性 | 专门实验/模型论文，保留测量窗口与机制范围 | 专业来源用于追溯，不从家族标签推断 | 先确定待检验机制、有效模型和可区分的实验结果 |

测量方法与计算方法现在必须分别提取、计缺失、交接与显示。衍射可以是结构测量
线索，泛 DFT 可以是结构/电子态/EPC 方法线索；它们不能自动成为 Tc 方法。
所有补全先保留为来源候选，核对 source/result/state 后再进入已有正式审查途径。
历史封存数据和标识不重写。尚无适用审查合同的字段需要独立版本合同，而非借用其他字段。

## 3. 本轮实现的 Discovery 页面层

- 首屏短定义、300 K/1 atm 研究目标和“证据 / 研究设计 / 方法范围”导航。
- 科学矩阵继续显式选择冻结发布版本；保留代表状态、原RPS、来源pins与审查边界。
  详细政策说明折叠，避免首屏铺满说明。
- 对选中的同一状态，将原生8个字段组织为 Host、Electronic activation、Pairing、
  Coherence 四阶段。显示实际数量、availability与局部review，保留 unknown、
  not computed、not applicable、conflicted 的含义。126字段字典仍是独立draft字典。
- 本地研究草案支持8种修改类型，最多组合8项成为一个拟议状态，描述修改参数、
  目标条件、配对假设和下一步行动。无来源时可写无来源支持的草案，不能出现示例数据回退。
- 导出带SHA-256的有限JSON：来源状态与新提议分开，附精确publication/result/state/
  structure/run/source pins；不继承改前科学结果，不创建正式材料/谱系，不提交计算或重算RPS。
  切换来源或离开页面清理旧关联，迟到的异步结果无效。

这一层是有用的研究设计入口，尚不是已运行的宿主库、大规模候选生成、真实压力扫描或闭环模型。

## 4. 完整 Discovery 数据模型与后续工程包

| 工程包 | 要落地的合同/行为 | 完成证据 |
|---|---|---|
| D1：Host library | 独立版本的host proposal；材料/结构revision、来源、适用T/P及稳定性证据；proposed/reported/reviewed分别保留 | 有真实来源的试点清单及逐项状态，不将讨论中的“50个”当数据量；结构或revision漂移使旧支持失效 |
| D2：Modification genealogy | 类型、位点、物种、浓度及基准、charge/strain/interface定义、before/after引用、关系证据；有向无环版本关系 | 防循环、同节点自联、名义与实测混用、unknown δ→0、interface→bulk、private parent泄漏的测试 |
| D3：Candidate generation | 选定host与修改集合，先估算再有界enumerate；去重、约束、拒绝原因、dry-run manifest与确定性输入摘要 | 组合数与上限一致；未知结构/位点/浓度不自动填；生成proposal与正式result分离，不自动提交大批DFT |
| D4：Pressure→ambient | 显式选择同材料的多个状态；same component/units/method/normalization及结构可比性判定 | 实际可比结果才画响应曲线；不解析state_summary为压力扫描，目标ambient与已报告压力分开 |
| D5：Design space | 每个轴有实际量、单位、状态范围、缺失策略与领域适用性；无跨家族通用潜力分 | 每个点可追溯到状态与结果；RPS/D1-D3 policy anchors不伪装为物理坐标，缺失值不落到0 |
| D6：Next action / closed loop | 候选→假设→至少两个可区分结果→继续/停止/改向决策；计算/实验prerequisites、预算、执行receipt、结果回流 | 原RPS发布语义与pins保持；缺失成本不等于免费，未执行任务不记为计算结果 |
| D7：Multistage models | structure→electronic→pairing→coherence；机制中立、时间/来源隔离、单位与归一化、post-outcome泄漏控制 | 独立human gold、按材料/论文/state切分、校准与外部验证；预测Tc与实验观察分开，未审训练用途不获ML授权 |

新模型使用新合同和migration，冻结的旧合同保持原义。先以少量来源充分的状态验证
整条链，随后按成本与真实数据覆盖扩展；不为了表格完整而制造量或相互拼接不兼容结果。

## 5. 界面和验收标准

Materials 默认短说明、基本筛选、7列核心信息；高级筛选、字段覆盖与方法范围折叠。
材料详情按“结果与条件→来源→可补字段→外部参考→下一步计算/实验”组织。
重复的无异常政策说明集中到页面范围说明，只有实际需处理的异常突出到行级。

Discovery 的默认阅读路径是“选发布版本→选状态→看四研究问题→准备草案→导出→按
真实prerequisites执行→回流来源结果”。表单采用CSS grid与一致label/控件高度；
320/390/1280 px下页面本身无横向溢出，宽比较表允许独立滚动且键盘可操作。
科学单位、源值/区间/不确定度不得因布局改动被改写。

验收包括：有意义的反例回归、原生receipt篡改/hold/drift防护、异步与visibility清理、
来源支持与用户假设分离、实际浏览器键盘/折叠/导出及下载内容核验。Synthetic fixture
只验证工程行为；真实科学增量用固定样本、真实来源、独立审查和正式reader消费验证。

最终发布仍需当前精确Git head的全部CI、签名release、备份与schema校验、正常SLO门槛、
部署连接配置核对，以及线上API/页面/筛选/分页/JSON导出的version fence验收。
论文候选数量、结构参考数量、RPS分数、页面上线都不能替代科学字段正式完成率。


## 6. 私有方案账本与逐记录完整度（2026-10-04 后续实现）

材料页新增独立 `materials-record-field-coverage/1.0.0`。每个字段分别统计
present / missing / unchecked / not_applicable，分母是当前可见且可用的保留记录。
最多检查32条，未检查部分仍进入分母；一条有值不能把整种材料标成完整。
真实历史抽样 YIn₃ 的压力为4/5条有保留值、1条缺失；这个数是保留记录检查，
不代表压力已核实、独立实验次数或正式科学补全。旧报告摘要和候选身份不重写。
新统计在旧报告封印和两次既有来源种子合并之后独立附加，下载包含其独立摘要。
旧接口响应继续可读，但没有逐记录分母时明确仅表示至少一条检查记录有提取。
空记录清单与全部不适用字段单独说明；无法核验的新统计不显示错误完整率。

Discovery 新增 `/dashboard/research/discovery-designs` 私有方案工作台和0087独立
append-only账本。默认关闭，读写都需显式curator；站点admin或reviewer身份不能
替代该角色。方案包含host标签、拟议状态、1–8项修改、目标压力/温度、配对假设、
下一步问题、前置条件、至少两个可区分且改变决策的结果，以及五类资源预算。
预算未知保留unknown；显式0与未知分开。来源可选无来源草案、确切保留结果或
原生科学property；来源范围、源状态和run仍属于基准，修改后不继承科学值。

流程为加载当前基准→预览确切方案→保存私有版本→检查历史。修订和撤回固定
前一版本；另起关联草案固定父方案版本与摘要。禁止循环、自联、跨owner关联和
撤回后复活。保存响应不确定时只按原request key/摘要GET查询，不重复POST。
切换身份或离开页面清理私有内容，后台任务迟到后不能重新展示旧内容。
源撤回、审查hold或基准漂移会保留历史回执并隐藏当前来源值。可见projection有
独立确切字节摘要，公开私有回执不包含原始科学subject/source closure。
前端在异步摘要校验前复制输入，防止校验中间修改authority、selector或内容。

这推进了D1/D2的私有假设与版本关系、D6的行动准备；尚未建立已认证稳定宿主库，
未执行修改、实验或计算，未产生新Tc预测、物理压力扫描、校准模型或新的RPS。
真实来源补全、样品/相/run关联、独立human gold、正式字段审查和线上验收仍是
全目标的后续工作。详情见 `discovery_research_design_protocol.md`。

## 7. 有界条件组合工具（上一阶段实现）

私有方案历史中的当前、有来源且可用的提案，可以输入明确的压力与温度离散集合。
先估算原始与去重组合数，再生成最多64项条件方案；每轴最多8项，不静默截断。
相同十进制值的不同写法精确去重，原始输入保留；不使用浮点舍入合并不同精度值。
ambient、指定0 GPa和未知压力分开；0 K与未知温度分开。没有隐含300 K或常压默认值。

生成清单保留父方案版本、来源pins、用户假设和下一步行动，只改变请求条件，
不继承原始科学结果。输入、候选身份和完整manifest分别有摘要；候选身份不受
参数顺序、等值写法及刷新会话影响。预算保持用户输入，批次总成本未知或未汇总。

用户挑选一项后进入既有私有子方案表单，必须重新加载当前基准、预览并显式保存。
上一阶段批次为本地manifest，JSON可下载；保存只保留方案条件和父版本，当时尚未保存
生成批次或候选关联。因此这是D3条件搜索的实际入口，不能宣布原子候选生成、
压力扫描或科学闭环完成。第8节补充独立批次接收与持久关联，结构/位点合同仍待实现。
详情见 `discovery_condition_sweep_protocol.md`。

## 8. 条件批次历史与原生子方案（后续代码实现）

独立默认关闭的私有批次接口，接收当前父方案版本和原始条件集合，由服务器重建
生成清单，核对输入及清单摘要后保留。原始生成清单的 `batch_saved:false` 保持原义；
“已保留”的事实由独立回执表示，不通过修改历史 JSON 获得。

研究者可以查看自己的批次、每页8项候选、导出原始清单和文件字节校验和。选择
候选后单独预览、显式保存第一版子方案；子方案与批次关联在同一事务中保存，
预览或关联失败均不遗留子方案。每个批次候选仅有一个初始关联，后续修改继续
使用普通方案版本历史，原始父方案保持不变。

保存需要当前 curator 授权、会话和可用来源。来源变化、父方案修订或撤回后，
历史清单仍可读取，界面说明暂停原因并禁止新增子方案。刷新会话不重写原清单的
生成身份；保存结果不确定时，只读取原请求的 outcome，不能自动重复写入。
派发保存后锁住编辑；离页清除私有显示内容，同时仅保留原请求的7项恢复pins。
同一用户刷新授权后可读取原结果，切换用户或认证身份则清除恢复信息。

独立测试数据库已验证真实 SQL/HTTP 的128项批次契约、事务和来源边界，以及7项
原有方案数值格式的实际接受行为。前端46项源码检查、2637项单元测试通过，
正常生产构建完成58个页面。真实浏览器重放原生SQL/HTTP合成回执，验证1280px
及320px布局、8项分页与后4项、打开既有关联，以及导出的20947字节与原始清单
完全一致；独立文件校验和覆盖实际UTF-8文件字节。浏览器重放不冒充数据库交易，
真实交易由独立后端测试验证。另有42项既有方案回归通过（1项重复空占位跳过）、
48项schema生命周期检查和真实空库到0088及回滚保留演练通过并确认测试服务清理。
这些工程证据不证明宿主稳定性、物理谱系或科学预测有效性；当前提交的CI、
正常发布及线上验收仍待完成。
SQL guards 执行确切来源 closure、显式治理与32层祖先限制；完整 catalogue 的
parser/anomaly policy 另由 HTTP 当前资格检查执行，未宣称两者全规则等价。
详情见 `discovery_condition_batch_protocol.md`。

## 9. 真实来源比较，而非条件目标充当科学结果

Discovery 新增 AB₂H₂₄ 原论文 Table I 的完整 21 个计算化合物比较。
共同条件为 300 GPa、isotropic Eliashberg、假设 μ*=0.1；原表 λ、Tc/K
及未印单位的 ωlog 各自保留。研究者可按 A/B 金属筛选，选择两项对照，
在固定 λ–Tc 物理坐标上查看原值，并导出完整表及来源定位。
图不回归、不连接成压力曲线；不同化合物的金属标签不能建立物理父子结构。
原表动态稳定的作者选择说明、类别层级的热力学限制，以及摘要 276 K 与表中
300 K 的差异分别保留，不转成全局科学接受或环境压力存活结论。

新增 NbScTiZr 退火来源比较入口，对接 Materials 的两篇明确版本论文。
2023 交流磁化率起始 Tc、2024 Hc2 分析 refined Tc、M/ρ 两种 WHH 结果
保留各自范围；相成分、晶格、两相比热和 GL 推导量按来源展开。
退火温度是处理条件，as-cast 不赋 0°C，跨篇同名处理组不等于同一实物样品。

这使 D3/D5 的来源比较有实际科研输入，未完成 D4 的同一状态多压力数据、
原子候选生成、宿主认证、已执行闭环或校准模型。元数据忠实度由原始 PDF、
固定提取文本和逐值定位检查验证；其结果不替代独立领域人工审核。
工程验证、提交 CI、正式发布和线上验收分别记录，不把本地页面称为上线。
实现和数据边界见 `discovery_source_comparison.md` 与 `materials_nbsctizr_annealing.md`。

## 10. 同一化合物的来源限定压力比较（后续代码）

## 11. 已有来源证据回传到研究决策（D6 的首个范围）

私有研究方案现在可以给一个确切的来源核查行动回传已有 retained record。
页面分别展示预期结果、研究者实际记录的发现、continue / stop / redirect 决策、
