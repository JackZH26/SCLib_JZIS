# V2 final source barrier

The existing fresh final-source check accepts an explicit internal
`RetrievalPinV2` in addition to its unchanged v1 default. It re-resolves the
authoritative active backend in the new read-only repeatable-read snapshot,
compares content/build/event/root/policy/profile and the complete selected
input digest, then hydrates exact retained origins. A prior private object or
public mapping cannot authorize itself. Missing, mixed and unbound selections
fail closed. Rollback to the same physical build with a new event invalidates
the old selection (ABA protection).

The shared source lifecycle, explicit material holds, evidence/renderer,
historical permission restrictions and Work-mapping checks still run. A
successful result describes one fresh snapshot; it grants no scientific
approval or future stability. Private v2 snapshots remain readable after
mutable Chunk deletion. V1 history, receipt bytes and the default checker are
unchanged. This opt-in component does not yet switch public routes.

Real fresh owned-database tests cover legacy/native retained members, deletion,
live source holds, renderer changes, permission restrictions that survive
mutable-row deletion, Work mapping changes, ABA activation/rollback, forged or
mixed pins, and withholding final details after a failed check. No production
or restored-clone pytest execution is involved.
