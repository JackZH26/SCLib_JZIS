# Content scientific and mixed response contracts

Live Search/Ask/Similar models now understand the explicit content/backend read
identity. Scientific rows additionally bind the content-member hash and the
real legacy or native origin, with vector/content/revision hashes and the
existing exact evidence/extraction parent. A native row cannot acquire a
provider generation. A retained origin keeps its actual old generation inside
the new content reference. Every scientific row must match the response's
content/build/event/manifest/policy, and completed lookup declares the content
scope. Scalar quantity, condition, unknown-value and non-approval rules stay
unchanged. Structural parsing is not database authorization.

`scientific-mixed-evidence/2.0.0` handles the same separately bounded numerical
and original inventories with either exact legacy or native vector identities.
It preserves complete pair bindings, held/stale source rejection, reviewed-link
metadata and abstention from unsupported numerical synthesis. Legacy mixed
versions retain their original vector pattern and serialization.

The browser validates both explicit protocols and displays the content/backend
and real origin separately. The v1 saved-answer decoder remains closed on both
server and browser, even as live unions grow: it rejects content read identities,
new scientific scopes and mixed v2 envelopes. Existing v1 rows, hashes and field
sets are unchanged. A separate v2 saved-answer capture/history implementation is
still required; this component does not relabel old receipts.

The new JSON fixtures are synthetic structural examples validated by the API
models, not HTTP route, retained-ledger, source-permission or quality evidence.
Compatibility checks exercise existing saved-answer round trips. Public routes
still use v1; lexical/formula/scientific execution, v2 history, publisher/queue,
full-site/load/recovery and coordinated rollout remain pending. This model
extension alone does not enable traffic or Google retirement.
