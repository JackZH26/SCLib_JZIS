# Content-pinned exact extraction lookup

`content_scientific_lookup` is an opt-in provider-free v2 reader. It discovers
derived evidence through exact legacy/native origins in the selected sealed
content. Retained legacy windows and original passages cannot acquire invented
extraction parents. Each eligible record must match the full immutable input
hash of its real extraction parent, evidence hash and retained origin.

The reader preserves existing scientific query parsing, quantity/pressure,
formula and same-record predicates, raw parent records and non-approval
semantics. Unknown years remain unknown. UI scientific filters retain opaque
English keyword conditions. A record cannot borrow another occurrence's
ambient pressure or promote a censored upper limit into a measured point.
Date/Tc sorting and parent deduplication occur after exact parent matching;
live source/permission/material holds still determine admission.

Prepared inputs expose explicit v2 content/build/event/root/policy plus real
legacy generation or native revision identities. Public results use the
existing closed `scientific-result-binding/2.0.0` contract and content scope.
They remain derived extractions, never original-passage support or independent
scientific acceptance. Private raw parent/context fields stay detached and
complete. The coordinator handle is single consumption and rejects inconsistent
result/parent/origin/selection inventories.

Preparation never commits, rolls back, calls a provider or finishes a caller's
transaction. The convenience lookup wrapper consumes once, ends its read and
uses the existing fresh v2 final barrier for every selected result, followed by
an authoritative pin recheck. A hold introduced after preparation withholds
all output. Deleting a mutable Chunk does not destroy a retained source.

The current complete preparation budget is 1,000 derived members, 5,000 records
and the existing retained-byte/parent-output limits. Over-budget input fails
closed; a top-prefix is never silently presented as complete. Before publishing
native collections beyond that budget, add a separately verified scalable
exact-result navigation/paging strategy. This component does not claim such
large native-collection acceptance. The current retained corpus has no
extraction parents and does not require hydrating its million legacy windows
for a negative exact-parent lookup.

Fresh owned SQL tests cover both origins, public response validation, preserved
raw fields, one-shot/detached inputs, original-only abstention, live holds after
preparation, mutable-row deletion, opaque keywords, pagination, unknown years,
censored values and cross-record pressure refusal. Existing v1 lookup and
public-contract tests run alongside them. Synthetic cases are not human gold.
Public routing, mixed-answer orchestration, v2 saved-answer receipts/history
and the native publisher remain separate integration gates.
